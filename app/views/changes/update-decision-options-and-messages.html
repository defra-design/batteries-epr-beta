Make a decision on one page, and see messages and notes on Submission details (EB-367)

Change

After the team walkthrough on 18 November, Marie reviewed the whole journey. These are the changes to making a decision, and why we made them.

Making a decision is now 1 page

Regulators select any members they want to query, select Continue to make a decision, and then do everything on one page. Before, there was a separate Selected members page first.

We removed the Selected members page because:

  • it had a box for a message about each member, but no user need asks for this
  • the boxes disappeared when a member was unticked, which was confusing
  • it added an extra step

The decision page lists the selected members at the top. Each member shows why it was selected: its flag, or if it has no flags, its largest change. This helps regulators remember what they wanted to ask when they write their message. There is no Change link, because it was not clear where it would take you. Regulators can use the back link instead.

We tried adding a Check your decision page before sending, but took it out. Everything is already on one page, so it would only have repeated it. Instead, the button says what it does: Send to the scheme.

Accept, query or return

Regulators can accept, query or return the submission, whichever members they have selected. Mak suggested that Accept should not be available when members are selected. David asked us to keep all 3 open for now and decide after research.

If members are selected, the Query option says the email will name them. If regulators query the submission, they must give a date for the scheme to respond by. Mak confirmed that regulators set this date and there is no standard period.

We now say "return" instead of "reject". This is the word the Environment Agency uses, and "reject" can sound negative. David and Mak are checking this with the Environment Agency working group.

What goes to the scheme and what does not

Regulators can write a message to the scheme. This is optional if they accept the submission, but they must write one if they query or return it. They can also attach a file.

Regulators can also add an internal note. The hint explains that the scheme will not see it, and that it can be read on Submission details. Regulators keep notes like this in the current system, NPWD.

We tried using headings to separate the message from the note, but took them out. The labels make the difference clear enough.

The confirmation page

The confirmation page now has one sentence under "What happens next". For example: "We've emailed Recycling Lives Compliance Services Ltd your query. They need to respond by 7 December 2026." We removed the line about the status changing on the list of submissions.

Messages and notes on Submission details

The list of submissions showed "Response received" for one submission, but nowhere showed what had been asked. The ticket needs the full back-and-forth with the scheme to be kept in the system.

Submission details now ends with a section called "Messages to the scheme and internal notes", newest first. Each entry says what it is (Query sent to the scheme, Acceptance sent to the scheme, Return sent to the scheme, or Internal note), when it was sent and who sent it. The section only appears when there is something to show.

In the prototype, decisions you make are not added to this section, and the submission's status does not change. Showing them would mean changing the status as well, which research does not need.

Other changes

  • The pages are now in this order: Flags, Members, Submission details, Changes, Scheme details. The 2 pages where regulators select members are next to each other, and Submission details is next to Changes.
  • The Members page heading is now "Members", to match the link to it.
  • The Changes page now starts with "Changes to the figures in this return." Selecting View changes takes you straight to that member's changes, not the top of their page.
  • "Overdue" no longer shows next to "Response received". The count of days stops once a query has been sent. ERP UK Ltd is now the example of an overdue submission.

Questions for research

  • Would regulators ever accept a submission after selecting members, or query one without selecting any?
  • Is it clear what goes to the scheme and what stays with regulators?
  • Do regulators look for the history of a submission on Submission details?
  • Where do regulators expect to go after sending a decision?

The wording in the prototype is a draft for content design to review.
