Show members 30 at a time, sorted on the server (EB-366)

Change

Members in version 4 now shows 30 members a page, with page links under the table. Recycling Lives has 281 members: on one page, that's a very long scroll, and over 560 tab stops for a keyboard user (a tickbox and a View figures link on every row).

Why 30

  • Alex's registration list shows 20. 30 is long enough to scan without changing page all the time, and still short enough to tab through. We can change it if research says so

Sorted on the server

  • Phil confirmed the APIs page and sort on the server (18 November). So the whole list is sorted, not just the page you're on. The MOJ sortable table we used before only sorted the rows on the page, which doesn't work once there are pages
  • Each column header is a link, with an arrow for the way it's sorted, the same as the Sorting column header in Defra Internal Frontend (Geoff's library). Press it again to turn the order round
  • Biggest change still comes first, biggest at the top. Member, Registration number and Membership sort A to Z first
  • The sort and page are in the address, so Back, bookmarks and sharing a link all work, and it works without JavaScript

Search and ticks

  • Search and Membership look at every member, not just this page, and go back to page 1
  • Ticks carry across pages: tick on page 1, go to page 2, tick more, then Make a decision. Without JavaScript, ticks save when you press Make a decision, so press it before changing page
  • No Select all on Members, so paging doesn't change what Select all means. Flags has under 30, so it isn't paged

To test with regulators

  • Is 30 a page right, or do they want more?
  • Do they sort by anything other than Biggest change?
